# 신고 추출 — 짧은 물건 이름 거절 고치기 전후

`eval/run_extract.py` — 같은 문장을 5번씩 추출(운영 프롬프트·모델 `gemini-3.6-flash`·thinking 설정 그대로). 오늘 날짜는 코퍼스 시점 2026-08-31로 고정.
'틀림' = 신고 세트에선 '신고 아님'으로 거절(운영에선 검색 없이 "분실물 신고가 아니에요"), '신고 아님' 세트에선 신고로 받아 검색까지 감.

- `before`: 프롬프트 `apps/agent/prompts/extract.txt (고치기 전 — FIND-60부터 쓰던 것)` · 호출당 입력 282 / 출력(thinking 포함) 55 토큰 · 135.1s<br>"문장이 '잃어버린 물건 신고'가 아니면(일반 질문·잡담·명령·욕설·광고 등) false" 한 줄, JSON 맨 앞이 is_lost_report.
- `v2`: 프롬프트 `초안 — 아래 after의 신고 판정 규칙 + 값 한국어 통일 규칙(채택 안 함)` · 호출당 입력 576 / 출력(thinking 포함) 57 토큰 · 131.1s<br>더한 규칙: item·color·category·features는 한국어 낱말로(backpack·リュック·双肩包 → 백팩), brand는 한국 브랜드면 한국어·외국 브랜드는 원어 로마자. '애매하면 true' 줄 없음, is_lost_report는 JSON 맨 앞. 거절은 0이 됐지만 받은 회차만 보면 외국어 1위가 오히려 낮아 채택 안 함(4절).
- `after`: 프롬프트 `apps/agent/prompts/extract.txt (고친 뒤)` · 호출당 입력 486 / 출력(thinking 포함) 62 토큰 · 154.5s<br>신고/아님 기준을 나열 + 짧은 물건 이름 예시(시험 문장과 겹치지 않게) + '애매하면 true' + **is_lost_report를 JSON 맨 끝으로**(값을 먼저 뽑고 판단). 맨 끝으로 옮기기 전(같은 규칙, 맨 앞)은 5회 측정 두 번에서 'Himalayan pink salt cleansing foam'만 1/5 거절 → 이 문장만 30번: 맨 앞 15/30 신고, 맨 끝 30/30 (같이 30번씩 돌린 '아이폰 16 프로 가격 얼마예요?'·판매 글·습득자 글·사용법 질문은 둘 다 0/10 신고).
